# Phase 3: BM25 Keyword Search + RRF Hybrid

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add BM25 keyword search (SQLite FTS5, stdlib) and Reciprocal Rank Fusion with dense search; measure `bm25` and `hybrid` against `dense`, with p-values computed by `kb bench` itself.

**Architecture:** `build_index` writes the same chunks to ChromaDB (dense) and to `bm25.sqlite` (an FTS5 table, `porter unicode61` tokenizer, chunk metadata in UNINDEXED columns). `searcher.search` dispatches on `settings.search_mode`: `dense`, `bm25`, or `hybrid` (top 50 from each, fused with RRF k=60). Query words are extracted with `\w+`, double-quoted and OR-joined, so user punctuation can't break FTS5 MATCH syntax and BM25 behaves like classic OR-retrieval. `evals/stats.py` holds a paired randomization test; each bench result stores per-query nDCG@10, and `results/summary.md` shows delta and p against the `dense` row.

**Tech Stack:** `sqlite3` FTS5 (verified available: SQLite 3.45.3). No new dependencies.

## Tasks
1. **Stats (TDD):** `paired_randomization(a, b, n=10000, seed=0) -> float`. Tests: identical lists -> p = 1.0; a consistent +0.2 shift over 50 queries -> p < 0.01.
2. **RRF (TDD):** `rrf(rankings: list[list[str]], k=60) -> list[str]`. Test: `[[a,b,c],[c,a]]` -> `[a,c,b]` (a = 1/61+1/62 > c = 1/63+1/61).
3. **BM25 store (TDD), `src/mcp_kb/bm25.py`:** `write(db_path, rows)` and `query(db_path, text, n) -> list[dict]`. Tests: exact identifier `ERR_4021` is found; a query with `rollback.sh C++ (urgent) "quoted"` doesn't raise; a query with no word characters returns `[]`; a missing database returns `[]`.
4. **Wire up:** `build_index` writes BM25 rows; `searcher.search` dispatches on `search_mode`; `Settings` gains `search_mode="dense"` and `candidates=50`. Tests: `bm25` and `hybrid` modes return valid citations; the regression gate passes in all three modes.
5. **Bench:** setups `bm25` and `hybrid`; `_ensure_index` rebuilds when `bm25.sqlite` is missing; results store `per_query` nDCG@10; summary gains "Δ vs dense" and "p" columns. Re-run `dense`, `bm25`, `hybrid` on all three datasets.
6. **Decide the default mode from the numbers**, then update README and commit.

## Exit check
- All tests pass; summary shows Δ and p for every non-dense row.
- The default `search_mode` is whichever setup the numbers support, with the reason written in the README.
